## 6. 用「打包产物」再验一遍（2026-09-30 补充）

上面第 1–4 节装的是**本地目录 link**，`dsh plugin add <目录>` 会把工作树直接链进去——
也就是说它证明的是"源码能跑"，**不等于**"发出去的 tarball 能跑"（`files` 少列一个文件、
`exports` 写错，都会只在消费者那边炸）。

所以又做了一遍，这次装的是 `npm pack` 出来的 tarball，且是**全新的隔离 DSH_HOME**：

```
$ dsh --profile web-tgz --from-default-profile web --dump-config
$ dsh plugin --profile web-tgz add ./dsh-dev-backup-1.0.0.tgz
+ dsh-dev-backup file:/Users/.../dsh-dev-backup-1.0.0.tgz
Packages: +4   Done in 305ms
```

（注意是 `file:` 而不是 `link:` —— 真的走了打包安装路径。）

- **profile 组合**：`--dump-config` 里出现 `# == dsh-dev-backup` / `- id: dsh-dev-backup`
- **Host 路由**：`GET /dsh-dev-backup/status` 返回真实状态
  （`level=bad`、`reasons=[failure-not-superseded]`、`ageHours=0.20`、
  `freshness=/Users/lu.haotian/Library/Logs/dev-backup/last-ok`）
- **启动日志**：除了一条与插件无关的 Node `DEP0180` 提示外，**无 error / warn**
- **Client 模块**：以包名注册 —— `plugins/??dsh-dev-backup/client.js&rev=25209d7839d3`；
  取回 **HTTP 200 / 14732 bytes**，内含 `__ModuleLoader__`、`id: 'dsh-dev-backup'`、
  `settings.dshDevBackup`

架构说明：插件是纯 JavaScript（无原生扩展），因此与 CPU 架构无关；
本节与上面各节都是在 **arm64** 机器上、**DSH 0.2.0-rc.2** 下实测的。
